# Security checklist

How each of trunc's security rules is enforced, and the test that shows it. Last reviewed 2026-10-11. A rule without a test is listed as a gap.

## Hostile archive contents

| Rule | Enforced in | Tested by |
|---|---|---|
| Entry paths are relative, NFC, `/`-separated; no `..`, `.`, empty components, drive letters, control characters. `.trnc` names, and on Windows all names, also exclude `\`, `:`, Windows-reserved names (including `CONIN$`, `CONOUT$`, `COM¹`–`COM³` and `LPT¹`–`LPT³`) and trailing dots/spaces (ADR-0014) | `trunc-core::path::validate` for every manifest entry; `trunc-core::path::validate_host` for ZIP, tar, ISO, container-image and single-file outputs | `trunc-core` path and manifest tests (`rejects_every_windows_device_name`, `rejects_staging_directory_name_and_new_device_names`); `hostile_manifest_is_rejected_at_open`; `rejects_hostile_names`; `hostile_archives_are_refused_untouched` |
| No top-level entry is named like the staging folder (`.trunc-stage-*`, compared with the collision key), for every format: it would pass the up-front "already exists" check and clash only at the final rename, after the whole archive was consumed | `trunc-core::path::validate_with` (`STAGE_PREFIX`) | `rejects_staging_directory_names_at_the_top`; `staging_directory_names_are_refused_at_the_top` (tar and ZIP); `late_name_clashes_are_refused_untouched` |
| When consuming into the archive's own folder, no top-level entry is named like one of its sidecars (`.trncr`, `.trncj`, `.trncj.tmp`, the gap log `.trncg`, `.receipt`), compared with the collision key | `stage::sidecar_conflict`, called by `consume`, `consume_zip` and `consume_stream` | `late_name_clashes_are_refused_untouched` |
| No duplicate names and nothing nested under a file. Duplicates are compared with the collision key for `.trnc` and on Windows and macOS (each character to its simple uppercase, then its simple lowercase, so `ı`/`i`, `ſ`/`s`, `ς`/`σ` and the Kelvin sign `K` (U+212A)/`k` collide as they do on NTFS or APFS), exactly on Linux. Outputs are checked against the exact name the filesystem reports | `Manifest::validate`; `zip::parse`; `tar::Reader`, `iso::parse` and the container-image merge (`host_key`); `trunc-core::path::collision_key`; `check_exact_name` | `rejects_case_collisions_and_nesting_under_files`; `collision_key_matches_ntfs_and_case_folding`; `names_ntfs_upper_cases_together_collide_up_front` (tar and ZIP); `rejects_hostile_names`; `hostile_and_unsupported_archives_are_refused_untouched` |
| Names that the filesystem folds together anyway are never merged into one output. NTFS case pairs are refused up front, before anything is freed; 8.3 short names like `LONGFI~1.TXT` and anything else the key misses are caught when the output is opened | collision key (above); `stage::check_exact_name`: an output that already exists must be listed under its exact name | `late_name_clashes_are_refused_untouched` (pairs refused with the archive untouched); `check_exact_name` itself by code review, with the crash sweeps covering the legitimate resume case |
| Block table tiles the stream exactly; sizes bounded; footers match the manifest | `Manifest::validate`, `Footer::decode`, `Archive::read_footer` | manifest and footer unit tests; `decode_never_panics` property tests; fuzz targets `header`, `footer`, `manifest` |
| Every byte is hash-checked before use (payload before decompressing, decoded block, whole entry) | `Archive::decode_block`, extract/consume hashers | `tampered_payload_is_detected`; `tampered_block_stops_before_destroying_it` |
| Compressed tarballs and files: the content between checkpoints must hash as it did in the scan before its compressed bytes are freed | `streamconsume::scan`, `consume_stream` | `corruption_is_found_before_anything_is_destroyed`; crash sweeps in `streamconsume.rs` (`crash_sweep_every_codec`, `crash_sweep_single_file`, …) |
| ZIP punch mode: each checkpoint's running CRC must match the verification pass before its bytes are freed | `zipconsume::verify_checkpoints`, `extract_punching` | `crash_sweep_punch_mode` |
| Manifest corruption is detected even when unsigned | BLAKE3 of the manifest region in the header | `tampered_footer_and_manifest_are_detected` (flips every 5th byte of header and manifest) |
| ZIP: central directory entries match their local headers; data stays before the directory; descriptor CRCs agree | `zip::parse` | `rejects_unsupported_and_inconsistent_archives`; fuzz target `zip`; `tampered_archives_never_panic` |
| ZIP: overlapping entries (zip-bomb technique) refused unless `--allow-overlap` | `consume_zip`, `extract_zip` | `overlapping_entries_need_opt_in_and_then_extract_correctly` |
| Decompression bombs: output never exceeds declared sizes; declared sizes are checked against free space first | `Inflater` `max_out`; block decoder exact length; preflight in `consume`, `consume_zip`, and the CLI `x` path | `output_limit_and_overrun_are_errors`; `zip_bomb_is_refused_by_the_space_check`; `refuses_up_front_when_space_is_clearly_short` |
| Memory stays bounded whatever the archive declares: non-destructive `.trnc` extract and verify decode at most 512 MiB per round (at least two blocks); tar entry names total at most 1 GiB per archive | `extract::round_end` (`ROUND_MAX_U`); `tar::Reader` (`MAX_NAME_BYTES`) | `rounds_cap_decoded_bytes`; the tar name cap by code review |
| Decoders never panic on garbage | all decoders return errors | property tests (`garbage_never_panics`, `corrupted_streams_never_panic`) and fuzz targets |
| Compressed streams: the scan decodes everything (checksums, tar headers, names) before anything is written; decoder memory is bounded by `--max-window`; a resumed decoder's window read back from disk must match the CRC journaled with it | `streamconsume::scan`; `Limits::max_window` in the xz and zstd decoders; `stream::restore_window` | `corruption_is_found_before_anything_is_destroyed`; `every_codec_on_structured_data`; fuzz targets `bzip2`, `xz`, `zstd` (differential against the reference decoders, with a resume from every checkpoint) |
| Parallel decoding only changes where work happens: a unit decoded ahead is used only if it starts exactly where the sequential decoder has reached (a bzip2 block-magic match inside compressed data is discarded); the xz index that locates blocks must pass its CRC, and anything unexpected falls back to sequential decoding; a BGZF member whose data does not match the size its header gives, or that is damaged, truncated or over the output limit, is left to the sequential loop, which gives the same output, checkpoints and errors as one thread; every unit still passes its codec checks (each BGZF member its CRC-32 and size); checkpoints depend only on the file, not the thread count | `stream::ordered_parallel`, `stream::with_ahead`; `bzip2::find_blocks`; `xz::whole_block_streams`, `xz::pre_decoded`; `zstd::whole_frames`; `gzip::bgzf_walk`, `gzip::bgzf_run` | `parallel_decoding_matches_sequential` (one thread and eight give the same output and checkpoints, BGZF included); `bgzf_with_wrong_sizes_or_damage` (wrong sizes, a lying header, damage, truncation, the output limit); `crash_sweep_independent_units` (BGZF included); fuzz targets `parallel_equiv` (one thread against four) and `resume_equiv` (resuming with a different thread count) |
| Parallel decoding is bounded on hostile input: units decoded ahead and not yet taken hold at most about 512 MiB (xz, zstd; BGZF in batches of about 2 MiB of output, at most threads + 2 batches ahead); an xz worker stops at the output size the index declares, and the index walk gives up on indexes over 16 MiB; bzip2 stops looking for parallel work past 4M block-magic candidates (256K per 8 MiB chunk); zstd walks at most 65536 frame headers at a time; a worker's panic is re-raised on the calling thread and the workers stop if the caller panics, instead of hanging | `xz::decode_block`, `xz::whole_block_streams` (`AHEAD_BYTES`); `bzip2::find_blocks`; `zstd` (`MAX_JOBS`, `AHEAD_BYTES`); `gzip::bgzf_run` (`BATCH_OUT`); `stream::ordered_parallel`, `stream::with_ahead` (`catch_unwind` / `resume_unwind`) | code review (commit 306b43c); the caps never change output or checkpoints, which the tests and fuzz targets above check |
| Split archives: a resumed consume accepts a missing part only if it lies wholly before the last checkpoint, and refuses parts whose size or file id changed | `source::Parts::reopen` | `split_archives_refuse_later_parts_and_replaced_parts`; `crash_sweep_split_archive` |

## ISO 9660 images (ADR-0015)

| Rule | Enforced in | Tested by |
|---|---|---|
| The tree is walked from the root directory record, never the path table. A directory extent visited twice (a loop to an ancestor, or two directories sharing records) is refused, as are overlapping directory extents and file data over directory records | `iso::parse` (`visited` set); `iso` overlap check after the walk | `hostile_images_are_refused` (loops to the root and to the parent, a file over directory records, primary and Joliet trees) |
| Every extent lies inside the file; multi-extent files are joined only when their sections are contiguous and whole sectors; truncated images and images without descriptors are refused | `iso::parse` | `hostile_images_are_refused` (file and directory extents past the end, a size of `u32::MAX`, truncation); `non_contiguous_multi_extent_is_refused` |
| Absurd counts are refused: more than 2^21 entries, 512 MiB of directory records, 256 levels, 16 chained continuation areas or 64 KiB of system-use data per record, 64 MiB of continuation areas per image, 64 volume descriptors | `iso` (`MAX_ENTRIES`, `MAX_DIR_BYTES`, `trunc-core::path::MAX_DEPTH`, `MAX_CONTINUATIONS`, `MAX_SUSP`, `MAX_CE_TOTAL`, `MAX_DESCRIPTORS`) | `absurd_depth_is_refused`; `looping_continuation_areas_are_refused`; `corrupt_images_never_panic` (thousands of randomly damaged Rock Ridge and Joliet images); the other caps by code review |
| Names from Rock Ridge, Joliet or plain records go through NFC, `validate_host` and the duplicate check, like ZIP and tar names: no `..`, control characters or `/` inside a name, no duplicates after `;N` versions are stripped. Symlinks, devices, FIFOs, sockets and associated files are skipped | `iso::parse` | `invalid_names_are_refused`; `rock_ridge_modes_symlinks_hidden_and_associated`; `symlinks_and_devices_are_skipped` |
| Files sharing an extent (hard links) and partial overlaps: extraction copies hard links in full; consuming any overlap, and extracting a partial overlap (which no authoring tool writes), needs `--allow-overlap`, and punch mode is then off | `isoconsume::extract_iso`; the ZIP consumer's overlap rule (`zipconsume::consume_layout`) | `shared_extents_need_opt_in_to_consume_but_not_to_extract`; `partial_overlaps_are_refused_for_extraction_too`; `shared_extents_are_counted_not_refused`; `partial_overlaps_are_counted` |
| ISO 9660 has no checksums, so `--consume` computes every file's CRC-32 before anything is released and stores it in the journal; the ZIP consumer then checks each file against it before its bytes are freed, also after a resume | `isoconsume::checksummed`; `zipconsume::verify_checkpoints`, `extract_punching` | `a_file_changed_before_extraction_is_caught_before_release`; `crash_sweep_entry_mode`, `crash_sweep_punch_mode` (in `isoconsume.rs`); `killed_iso_consume_resumes` |
| A hostile image is refused before anything is written or freed; an ISO journal (`TIJP1`) and a ZIP journal (`TZJP1`) are never resumed by the other consumer; a `.trnc` is never taken for an image | `isoconsume::consume_iso` (scan first); `zipconsume::Format`; `isoconsume::is_iso` (skips files with the `.trnc` header magic) | `hostile_images_are_refused_untouched`; `zip_and_iso_journals_are_not_mixed_up`; the `.trnc` check by code review |

## Container images (ADR-0016)

| Rule | Enforced in | Tested by |
|---|---|---|
| Every layer blob is hashed against its digest (when recorded) and its decoded tar against the config's `diff_ids`, in the scan and again while writing; every JSON blob reached through a descriptor is checked against its digest and size | `image::check_digest`, `image` layer decoding and descriptor reads | `layer_digest_mismatch_is_refused` (a tampered gzip blob; a wrong `diff_id` on an uncompressed `docker save` layer) |
| Blob paths are built only from `sha256:<64 lowercase hex>` digests (`blobs/sha256/<hex>`), so a manifest cannot name anything outside `blobs/`; `docker save` layer paths must be among the outer tar's validated entry names | `image::blob_path`; `image` layer lookup | `digests` (unit test: `../`, uppercase hex, `sha512`, bare hex refused); `missing_blobs_and_paths_outside_blobs_are_refused` |
| A layer's declared media type must match its actual compression; encrypted layers are refused | `image` layer checks | `media_type_must_match_the_blob` |
| Whiteouts cannot escape or misbehave: empty, `.` and `..` whiteout names, entries inside a whiteout and whiteouts that are directories are refused; a layer's whiteouts apply only to lower layers | `image::merge_layers` | `whiteouts_cannot_escape`; `bad_whiteouts_are_refused`; `whiteouts_do_not_hide_their_own_layer` |
| Layer entries get the tarball reader's validation and refusals (unsafe names, hard links, sparse files); only the merged winners are written, into a staging folder renamed into place, and nothing is ever deleted; top-level names that already exist are refused | `image` scan (`tar::Reader`); `image` write phase (ADR-0003) | `hostile_names_in_layers_are_refused`; `hard_links_are_refused_clearly`; `existing_top_level_names_are_refused` |
| Image metadata is read by a strict JSON parser: duplicate keys, invalid UTF-8 or escapes, trailing data and nesting deeper than 64 are refused; documents over 16 MiB and index chains deeper than 4 are refused | `json::Json::parse`; `image` (`MAX_JSON`, `MAX_INDEX_DEPTH`) | `refuses_bad_input` (including 100 levels of nesting); the 16 MiB and index-depth caps by code review |
| `--consume` is refused for container images (a layer can be freed only once no later layer can change it, so consuming would save nothing), and the archive is left untouched | CLI `image_cmd` | `container_images` (CLI test) |

## Writing outputs

| Rule | Enforced in | Tested by |
|---|---|---|
| Never follow symlinks or junctions when opening outputs | `OsFs::open` (Windows: `FILE_FLAG_OPEN_REPARSE_POINT` + attribute check, junction detection on open failure; Linux: `O_NOFOLLOW`). Staged outputs and directories go through `open_beneath` / `create_dir_beneath`: on Linux `openat2(RESOLVE_BENEATH \| RESOLVE_NO_SYMLINKS)`, so no component below the staging folder can be a link; on Windows the opened handle's real location (`GetFinalPathNameByHandleW` plus the volume serial) must lie inside the staging folder, so nothing is written through a junction anywhere on the path, and an item created through one is removed again | `junctions_are_never_followed`; `symlinks_are_never_followed` |
| Symlink entries are never created by `--consume`; non-destructive extraction creates them only with `--allow-symlinks` and only when they resolve inside the destination, without passing through another symlink entry | `stage::build_structure`; `extract::symlink_stays_inside` | `symlink_containment` |
| Writes go only into the staging folder until the rename phase; renames never replace existing paths | `consume`, `consume_zip`, `OsFs::rename` (Windows `MoveFileExW` without replace; Linux `renameat2(RENAME_NOREPLACE)`) | `check_crash_state` in every crash sweep; `rename_never_replaces`; `refuses_existing_targets_and_wrong_destinations` |
| An output is never the archive or its journal under another name | `stage::open_staged_output` compares file ids | `refuses_staged_files_that_are_the_archive`; `refuses_staged_files_that_are_the_zip` |
| The space check never under-estimates the peak a consume occupies (a run that still runs short, for example because another program took the space, pauses with nothing destroyed). Property tests replay each consume loop on random inputs and compare the simulated peak with the planned one; they found three under-estimates (partial deallocation units at both ends of a punched range, the cluster past a half-written output's length when its source is released, and the gap log's own metadata), each fixed and kept as a regression test | `trunc-core::space::bound`, `space::batches`; `zipconsume::zip_space`; `streamconsume::stream_space` | `trnc_planner_never_underestimates_the_consume_peak`; `trnc_planner_holds_for_one_block_batches`; `trnc_bound_covers_a_file_released_half_written`; `zip_planner_never_underestimates_the_consume_peak`; `zip_planner_holds_in_punch_mode`; `zip_punch_estimate_covers_partial_units_at_both_ends`; `zip_punch_estimate_covers_the_output_cluster_at_a_checkpoint`; `stream_planner_never_underestimates_the_consume_peak`; `stream_bound_covers_the_open_file_and_the_gap_log` |
| setuid/setgid/sticky bits are never restored | `extract::apply_mode` (`mode & 0o777`); `OsFs::set_mode` | code review |
| Outputs cannot be modified by other processes during consumption | Windows: exclusive share mode (other handles may read only). Linux: advisory `flock`, which stops a second trunc but not other programs (see gaps) | `exclusive_open_blocks_other_handles`; `exclusive_open_stops_a_second_exclusive_open`; `exclusive_handles_and_create_semantics` |

## Known gaps and accepted risks

- **Local attackers racing the staging folder.** Consuming an archive into a folder that untrusted local users can write to is not supported. Within the staging folder, Linux 5.6 and later resolve every path with `openat2(RESOLVE_BENEATH | RESOLVE_NO_SYMLINKS)`, and Windows checks where each opened output really is, so data is never written through a link or junction below it; but a process with write access to the destination can still race trunc in these ways:
  - *The staging folder itself.* Each `open_beneath` / `create_dir_beneath` call opens the staging folder by path, following links, before resolving beneath it. A process that swaps the staging folder for a symlink (Linux) or junction between operations redirects what follows on Linux, and on Windows can briefly create an empty file or directory outside before trunc detects it and removes it.
  - *Staged subdirectories on Windows.* Swapping one for a junction can likewise briefly create an empty file or directory outside before trunc removes it.
  - *Linux `set_mode`.* Restoring a file's mode checks that the path is not a symlink, then calls `chmod` by path, which follows a link swapped in between (or a link in a parent component).
  - *Linux kernels before 5.6*, where openat2 is unavailable, fall back to check-then-open.
- **Case-insensitive destinations on Linux.** On Linux duplicate names are compared exactly. A destination that folds case anyway (an ext4 or F2FS casefold directory, a mounted NTFS, FAT or exFAT volume, an SMB share) is not detected up front, so two entries differing only in case pass every early check. The second is refused by `check_exact_name` when it is opened, partway through `--consume`, after some of the archive's space has been freed. Nothing is lost (the invariants hold, and the remaining content is still in the archive), but the consume cannot finish at that destination.
- **Linux advisory locking.** `flock` stops a second trunc, but other programs can still modify staged outputs, and such changes are not detected: a resumed run does not re-read output that was already made durable.
- **Integrity is not authenticity.** An unsigned archive can be replaced wholesale. Use signatures and `--trust-key` when the source matters.
- **Lying storage.** A drive that acknowledges flushes without persisting data defeats any ordering. `--verify-media` reads data back, bypassing the OS cache, before releasing source bytes; the drive's own cache may still answer.

## Verifying downloads

Every release lists the SHA-256 of each file in `SHA256SUMS` (and `<asset>.sha256`); `install.sh` and `install.ps1` always check it. Each target also has a CycloneDX SBOM, `trunc-<target>.cdx.json`, listing the crates compiled into that binary.

Releases built while the repository is public also carry signed build provenance (Sigstore, via GitHub artifact attestations), which ties each file to the commit and the `release.yml` run that built it. Check it with the [GitHub CLI](https://cli.github.com):

```sh
gh attestation verify trunc-x86_64-unknown-linux-musl.tar.gz --repo Sparsebits/trunc \
  --signer-workflow Sparsebits/trunc/.github/workflows/release.yml
# the SBOM bound to that archive:
gh attestation verify trunc-x86_64-unknown-linux-musl.tar.gz --repo Sparsebits/trunc \
  --predicate-type https://cyclonedx.org/bom
```

The install scripts run the first check themselves when `gh` is installed, warning (not failing) if it cannot verify, for example when gh is not logged in. Set `TRUNC_VERIFY_ATTESTATION=1` to make the check required, or `0` to skip it.
